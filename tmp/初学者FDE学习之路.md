# 初学者FDE学习之路

## 写在前面的话

FDE现在是一个特别火的名词，随着AI在企业里用得越来越多，FDE在接下来一段时间只会更缺。

对于非AI类的程序员或者产品经理来说，转型FDE可能是当前最好的选择。

但是，市面上的很多材料都特别虚，没有说到点子上。

本文就从一个初学者开始说，如果要开始学FDE，该怎么学。

## 面向谁

这篇文章面向对计算机编程有一定了解，并且（最好）会使用Claude Code或者Codex的朋友。

简单来说，最好能手搓，其次是能vibe coding出来下面的小东西：

1. Python能写一小段代码，读文件，会写循环，会写if、break等等。
2. SQL会对表进行增删改查，会join。
3. Git能拉代码、能提交。

然后照着这里做，[SQLite 数据库指南：从零开始掌握 Python 数据库操作](https://blog.csdn.net/2301_80216352/article/details/155320108)。会用Python对SQLite进行增删改查即可。

## 第一阶段 学习使用企业化使用Python

从市面上的工作需求来看，Python是最重要的技能，也是最常被要求具备的技能。这里，你需要学习的是用于企业级AI的Python，因为Python是一门内容非常广泛的语言。实际上，Python可以学的东西非常多，你可以持续每天花2-3个小时来进行学习。

但是，你不需要完全学完了Python后才进入第二阶段。你可以在有一定Python基础之后，尝试用Python + FastAPI来构建一个Web服务器。

总体来说你要学习的东西包括：

1. Python基础
- for循环
- 数据类型
- 变量
- if else等等

2. FastAPI
- 接口设计
- 后台任务
- 中间件

3. Pydantic
- 确定数据格式
- 自定义校验规则
- 嵌套模型
- 报错处理

4. 环境管理：用.env文件管理不同环境的配置
5. 在Python里调LLM API

### 作业

- 用手写一个工单跟踪的FastAPI服务，包含5个接口
    - 新建工单
    - 列出全部工单
    - 改工单状态
    - 按ID查工单
    - /summarize接口，调大模型给工单做摘要
    - 用Pydantic模型校验请求和返回的数据，报错处理要规范（HTTPException、格式统一的报错返回）
- 把项目推到GitHub，写个README

## 第二阶段 学习Vibe Coding

我们要做FDE，肯定要熟练掌握怎么用AI写代码。这个阶段我们开始学习如何Vibe Coding。

1. 选一个工具，建议是Claude Code或者Codex。
2. LLM方面，有足够经费，选择Opus 5.5，经费不够就使用DeepSeek V4.1 Flash。
3. Claude Skills、CLAUDE.md、上下文管理。
4. 和AI编程时养成好习惯。尽量拆成一步一步让AI来做，并且在过程中及时纠正和验证
    1. 先做方案设计
    2. 让AI根据方案设计好测试用例
    3. 再让AI执行计划
    4. 及时验证和测试
5. AI可能出错的地方包括，这些点都要自己去检查和不停向AI提问
    1. 给自己加戏，编造需求
    2. 报错处理乱写
    3. 忽略关键处理

### 作业

- 用Claude Code或Codex，给第一阶段的工单系统加功能
    - 先写一个CLAUDE.md
    - 给项目增加5个规范，包括命名、报错处理、文件夹结构、类型标注、不写死密钥
    - 再让AI加2个新功能：分配维修人员和任务优先级
- review AI的代码：让AI生成大约100行新功能的代码，然后不靠AI，自己找出并修掉至少3个问题

## 第三阶段 大模型基础和RAG

很多企业项目，一上来就要查自己家的文档：设备手册、人事制度、供应商合同。大模型自己不知道这些，只能现查现答，这就是RAG。这一阶段先把大模型是怎么回事搞明白，再动手做一套能查文档、能带出处的问答。

你要学的东西：

1. 大模型几个基本概念：temperature、top-p、top-k、上下文窗口。调这些参数，回答的风格和稳定性会跟着变。
2. Transformer大概是怎么工作的，不用背公式，知道它是一段一段往后生成、前面说过的话会影响后面就行。
3. RAG的整条链路：文档进来，先切块，再转成向量，存起来；问问题时，先检索，再把查到的内容交给大模型回答。
4. 切块怎么切：固定长度切、按段落递归切、按语义切，效果不一样，要试。
5. 向量库至少会用一个，比如ChromaDB、Qdrant、PgVector。
6. 检索怎么才准：只看语义不够，只看关键词也不够，两种混着来，再加一轮重排序。
7. 防胡说：回答必须有出处，查不到就说不知道，别让模型自己编。
8. 成本和延迟要一直算着：简单的活别用贵的模型，多试几个，选够用又便宜的。

### 作业

- 拿10份真实PDF做一套RAG，设备手册、人事制度、供应商合同都行。跑通灌入、切块、转向量、带出处回答这一整条链。
- 把这个项目推到GitHub，写清楚怎么跑、用了什么模型、花了多少钱。

## 第四阶段 Agent、多Agent和MCP

RAG是“问一句、答一句”。Agent是“交代一件事，它自己去查、去判断、去动手”。到了客户现场，很多活都是这种：报修进来，先查手册，再定优先级，再建工单。

你要学的东西：

1. Agent是怎么转起来的：想一想、动一动、看结果，再想一想，这就是ReAct循环。
2. 工具调用：给Agent的工具定好格式和边界，输出用结构化JSON，别让它自由发挥。
3. 用LangChain先做一个能干活的Agent，再做一个购物Agent练手。
4. 多Agent用LangGraph：状态、节点、条件边、记忆怎么存，都要会。
5. 人在回路：Agent信心不足，或者动作不可撤销，就停下来转人工。低于85%分、P1工单，都别让它自己建单。
6. MCP：把企业里的工具按标准暴露给Agent，别每个项目都重新发明一套接法。
7. 护栏和评测：Agent能干什么、不能干什么，先定好、先测好，别等客户先踩到坑。

### 作业

- 在第一阶段的工单系统上，做一个工单分派Agent：读报修，用RAG查设备手册，定优先级，再调接口建工单，全程走工具调用。
- 加上人在回路：信心低于85%或者P1，转到“待人工复核”，不自动建单。
- 录一个5分钟演示，像给客户IT团队讲一样，说清楚Agent是怎么做决定的。
- 再做一个3个Agent的LangGraph系统：一个抽询价单和供应商文件里的关键字段，一个对照批准供应商名单校验完整性，一个起草采购建议，发到模拟审批接口。

## 第五阶段 对接企业系统和数据

AI很少是凭空跑的，多数是长在企业原来的系统上面：ERP、OA、CRM、飞书、钉钉、企微。你要做的，是把这些系统里的数据拿出来，让AI用得上。

你要学的东西：

1. 先分清什么是“记录系统”，什么是主数据、什么是交易数据。工单、设备、人员这些数据，到底归哪个系统管。
2. 常见系统大概长什么样：SAP、用友、金蝶、自研OA，各自的模块都管什么，知道个大概就行。
3. 数据怎么拿出来：现成连接器、OData/REST接口、MCP服务，客户现场有什么就用什么。
4. REST接口的规矩：认证、限流、重试、幂等。重复调一次，不能重复建两张单。
5. 数据质量的现实：重复的主数据、看不懂的代码、过期的数据，都要先处理，别直接喂给模型。
6. 最关键的一项本事：知道该向客户IT团队要什么。数据字典、接口目录、权限、沙箱，一个都不能少，没这些就没法开工。

### 作业

- 调一个公开的SAP沙箱接口，把设备主数据拿回来，包括功能位置和维护工厂。不用装SAP，注册免费账号就能调。
- 写一个FastAPI接口把这个调用包一层，返回结构化JSON，再把它接成你Agent的一个工具。
- 写一页对接说明：来源系统、接口、认证方式、字段、刷新频率，写得像要交给客户IT团队看的那种。

## 第六阶段 部署上线：Docker、CI/CD

代码在你电脑上能跑，不等于在客户那里能跑。这一阶段学的是怎么把东西打包、部署、持续交付出去。

你要学的东西：

1. Docker：会写Dockerfile，会打包镜像，会推到仓库。镜像别做得太大。
2. Kubernetes：不用背全套，但要看得懂部署文件，知道服务、配置、密钥、资源上限是怎么回事，能把一个小服务部署上去。
3. CI/CD：用GitHub Actions跑一条流水线，检查代码、跑测试、构建、推送、部署，推到主分支就自动走。
4. API网关那一层：限流、认证、CORS、路由，知道是干什么的。
5. 密钥管理：密钥放专门管密钥的地方，别放环境变量里，更别写进代码。
6. 本地部署要知道有这么回事：有些客户数据不能出内网，要会用Ollama、vLLM在本地跑模型，知道离线仓库是怎么回事。

### 作业

- 把前面做的多Agent系统用Docker打包，推到Docker Hub或者云上的容器仓库。
- 写一个GitHub Actions工作流，推到主分支就自动跑测试、自动部署。
- 部署到一台云虚拟机或者云容器服务上，给一个能打开的链接。

## 第七阶段 LLMOps：上线之后别出事

系统上线只是第一步。真正难的是上线之后：用户在用，模型在花钱，偶尔还会答错。这一阶段学的是怎么看着它、测着它、管着它。

你要学的东西：

1. 链路日志：每次请求都记下来，输入、输出、延迟、花了多少token。用LangSmith或者LangFuse都行。
2. 看板：每分钟多少请求、P95延迟多少、报错率多少、每天花了多少钱，4个数先看住。
3. 评测：准备一套回归测试，定期跑，幻觉率有没有变高，一眼能看出来。
4. 成本：简单的活走小模型，只有真要精度的才走贵的模型。超出预算要报警。
5. 安全：提示词注入、数据泄露、输出没处理好，这几类问题要认得出来，也要知道怎么防。
6. 权限：多租户的系统，谁能看什么，要分清楚。对接单点登录那一套，要知道流程。
7. 压测：上线前先压一下，知道系统能扛多少人，扛不住的时候先降级，别直接挂掉。

### 作业

- 给你的Agent接上LangSmith或者LangFuse，抓50条不同类型工单的调用链路。
- 搭一个Grafana看板，至少有上面说的4个数。
- 写一份安全威胁模型：找出3个提示词注入的风险，写清楚怎么防。
- 用Locust压一下接口，50个并发，把结果记下来。

## 第八阶段 系统设计：HLD和LLD

调一个模型接口不难。难的是围着模型搭一套系统，又快、又便宜、又可靠，出了问题还不丢人。面试里也常从这里开始问。

你要学的东西：

1. 先搞懂客户现在的系统是怎么搭的，你加的东西别把人家现有的用法搞坏。
2. AI系统为什么不一样：模型不确定、贵、慢、还会一本正经地答错。每个设计，都是在防这四点里的某一点。
3. 模型怎么选：小模型做抽取和分类，只有真要综合判断才用强的。选错模型，成本一下就上去了。
4. 检索那一层：灌入和查询是两条路，混合检索、重排序、切分、元数据过滤。RAG答得差，十次里八次是检索的问题，先查检索。
5. 编排：流程固定的事，优先用固定流程；只有真开放的任务，才用开放式Agent。每步95%准，10步下来整体也就60%左右，这笔账要会算。
6. 延迟和成本：首token时间、流式输出、缓存、输出上限，都是设计时就要定好的，不是月底看账单才发现。
7. 信任层：输入输出护栏、评测、端到端追踪。出了问题，要能分清是检索坏了还是生成坏了。
8. 降级：主模型不行换备用模型，备用模型不行就体面地转人工，每一级都要告诉用户。
9. HLD和LLD：HLD说清楚有哪些组件、怎么协作、用什么技术、为什么、部署在哪；LLD说清楚接口、表结构、时序图，顺利的流程和出错的流程都要画。
10. 架构决策记录：定了什么、否掉了什么、代价是什么，写下来。画图用draw.io、Eraser.io、Mermaid都行，留住源文件。

### 作业

- 写一个AI现场服务管理系统的HLD：架构图、组件清单、技术栈和选型理由、部署拓扑、模型路由策略，再加一条模型托管方式的决策记录。
- 给同一个系统写LLD：至少8个接口的接口表、数据库表结构、工单创建的时序图，再画一张ERP写入失败时的时序图。
- 5分钟口头讲清楚你的设计，录下来自己复盘一遍。

## 第九阶段 先找到真问题，再动手

前面学的都是“怎么做”。从这里开始，学的是“做什么”。客户说头疼，你不能马上开止疼药，先问清楚，再动手。

你要学的东西：

1. 5 Whys：连着问为什么，找到根因再动手。
2. 提问的办法：问开放式问题，让对方没法用客套话糊弄你。别问“你想不想要AI”，要问“你现在是怎么做这件事的，哪一步最费时间”。
3. 跟岗：跟着做事的人走一遍，把他现在的每一步都记下来。
4. 分清两种需求：老板要的，和一线用户要的，经常不是一回事。两种都要听。
5. 调研前先要材料：制度文件、组织架构图、现在的流程指标。没这些，访谈就是空聊。
6. 把问题量化：出错率多少、手工花了多少小时、每次出错多少钱。说不清楚数字，就说不清楚值不值得做。
7. 范围蔓延要管住，保密协议、数据规矩、现场准入规矩，先问清楚。

### 作业

- 挑一个你真了解的流程，写一份访谈提纲，10个开放式问题。
- 真去访谈一个天天做这个流程的人，记下现在的步骤、痛点，量化出来：手工多少小时、出错率多少、每次出错多少钱。
- 写一页问题陈述，把业务影响量化，让受访者确认写得准不准。

## 第十阶段 把流程画出来

动手自动化之前，先把现在的流程画出来。这张图就是你和客户对“现实是什么样”的一致意见。

你要学的东西：

1. BPMN的基础：池、泳道、事件、网关、任务、连接线，会这几个就能画。
2. 画AS-IS：现在的流程是什么样，就画什么样，手工步骤别漏。
3. 找能自动化的步骤：重复的、有规则的、量大的、容易出错的，优先做。
4. 再跟相关方一起定TO-BE：AI进来之后，流程变成什么样。
5. 画图工具：draw.io、Miro都行。

### 作业

- 给上一阶段调研的流程，画一张完整的AS-IS泳道图。
- 把你想用AI自动化的步骤标出来，写清楚为什么选这些步骤。
- 把图发出来，配一段文字说你学到了什么。

## 第十一阶段 写BRD：把需求写清楚

企业客户先看你的文档，再看你的代码。文档写不清楚，代码写得再好也没用。

你要学的东西：

1. BRD的结构：摘要、范围和范围外、AS-IS/TO-BE、功能需求、对接需求、数据需求、验收标准、风险和假设。
2. 验收标准要能量化。别写“系统要快”，要写“工单分派在P95下不超过5秒”。
3. 范围要写清楚：哪些不做，为什么不做。
4. 版本管理：改了什么、为什么改，留记录。
5. 常见毛病：需求写得含糊、漏了排除项、验收标准没法测，这三样最要命。

### 作业

- 给你调研的那个流程写一份完整BRD，至少8个部分，功能需求表里至少10条需求。
- 找同行看一遍：每条需求有没有能量化的验收标准。
- 把BRD摘要整理成一篇文章发出来。

## 第十二阶段 写TDD：告诉开发具体怎么做

BRD说的是“要什么、为什么”。TDD是告诉开发人员，或者告诉AI写代码的Agent，系统具体该怎么表现。

你要学的东西：

1. 怎么从BRD推出功能流程和数据流程。
2. 字段级校验：哪些字段必填、格式什么样、容差是多少。
3. 业务规则：比如SLA升级，到SLA时长的80%先警告，到100%自动升级。
4. 出错场景和异常处理：出错了系统该干什么，一条一条写清楚。
5. 对接规格：来源系统、接口、认证、刷新频率。

### 作业

- 从你前面写的BRD推出一份TDD：功能流程、校验规则、异常处理、对接规格都要有。
- 写一条业务规则规格，流程图加规则表，写得像要交给开发人员的那种，然后喂给一个AI写代码Agent，看它能不能照着建对。建不对，就是规格没写清楚。

## 第十三阶段 跟人打交道

技术能让你进场，跟人打交道的本事决定你能不能在客户现场干成事。

你要学的东西：

1. 相关方有哪些：最终用户、流程负责人、IT把关人、出钱的老板。按影响力和关注度，先分清楚谁最重要。
2. 管预期：怎么体面地说不，怎么拿范围换时间，谈好的事要落到文字上。
3. 沟通节奏：会议议程、会议纪要、每周进展、升级路径，一样都不能省。
4. 给高管汇报：3页幻灯片就够，问题、方案、结果，一页一个。
5. 给不懂技术的人演示：讲结果，别讲架构。
6. 不确定的时候别硬撑，问清楚：“帮我理解一下，你说的是X还是Y？”

### 作业

- 写300字短文：FDE能解决什么问题，是解决方案工程师解决不了的？
- 录一个5分钟、3页幻灯片的高管汇报，讲你前面做的项目：问题、方案、结果。
- 找个朋友扮难缠的流程负责人，开一次模拟会议，练怎么顶住范围扩张，记一份会议纪要。

## 第十四阶段 UAT和上线

UAT是客户说了算的地方。上线是证明系统真能用的地方。

你要学的东西：

1. UAT和QA测试的区别：UAT验的是业务上能不能用，单元测试验的是代码对不对。
2. 写UAT脚本：场景、前置条件、测试步骤、预期结果和实际结果、通过还是不通过。
3. 进入和退出标准：开始UAT之前要满足什么，批准上线之前要满足什么，先定好。
4. 带真实用户做UAT：预期要管好，缺陷要分流，严重程度分严重、高、中、低。
5. 上线检查清单：数据迁移核对过、回滚方案写好、支持联系人列好。
6. 上线后重点保障期：升级矩阵、事故响应手册，先准备好。

### 作业

- 写一份15个场景的UAT脚本，覆盖P1紧急派单、SLA违约升级、备件缺货、维修人员技能不匹配。
- 找个朋友扮业务用户，真跑一遍UAT，记下发现的缺陷，先修P1的。
- 给你前面的项目写一份上线检查清单，带回滚方案。

## 第十五阶段 交接、培训、证明ROI

项目不是系统能跑就完了，是客户团队不用你也能自己用，才算完。

你要学的东西：

1. 用户为什么抗拒新系统：怕麻烦、怕出错、怕被替代。先理解这个，再想办法。
2. 培训要按角色来：不同岗位的人，看不同的指南、不同的视频，FAQ也要分开写。
3. KPI怎么定：ROI、效率提升、出错减少、SLA达标率，选客户看得懂的。
4. KPI看板：不懂技术的人也能看懂、能信，别堆一堆术语。
5. 交接文档包：架构总览、运维手册、联系人表、已知问题，一次交齐。
6. 上线后复盘：跑一段时间，回头看哪些地方还要改，形成循环。

### 作业

- 写一份3页的IT交接文档：架构总览、运维手册、联系人表、已知问题。
- 做一个KPI看板，至少有：处理工单数、一次修复率、SLA达标率、维修人员利用率、平均修复时间。
- 做一个10分钟的完整项目演示视频，像给客户高管汇报一样，把整个项目讲一遍。

## 加餐：SAP深入对接

这部分不是所有岗位都需要。如果你要去SAP很重的咨询公司，或者制造、现场服务的客户，再学。

要学的东西：BAPI、OData、RFC、IDoc、SAP CPI这些对接方式；SAP PM管设备和工单、SAP CS管服务单和合同；备件、SLA、排班、物联网触发工单，这些业务知识。

作业就一个：写一张BAPI对接目录表，列5个现场服务自动化的BAPI，新建工单、读设备主数据、确认工单工序、新建服务通知、查物料情况。
