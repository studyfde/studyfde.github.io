# 初学者FDE学习之路

## 写在前面的话
FDE现在是一个特别火的名词, 随着AI在企业里更多的使用, FDE必然在接下来的时间段会更加紧缺. 

对于程序员或者产品经理来学, 转型FDE可能是当前最好的选择.

但是, 现在的问题是市面上的很多材料都特别虚, 都没有说在点子上.

本文从一个初学者开始说,如果开始FDE课程

## 面向谁
这篇文章面向对计算机编程有一定了解, 并且(最好)会使用Claude Code或者Codex的 朋友. 

简单来说, 最好能手搓, 其次是能vibe coding出来下面的小东西

1. Python 能写一小段代码，读文件, 会写循环, 会写if, break等等
2. SQL 会对表进行增删改查, 会join.
3. Git 能拉代码、能提交.

然后照着这里做, [SQLite 数据库指南：从零开始掌握 Python 数据库操作](https://blog.csdn.net/2301_80216352/article/details/155320108)。
会用python对sqlite 进行增删改查即可.

## 第一阶段  学习使用企业化使用Python

从市面上的工作需求来看, Python 是最重要的技能，也是最常被要求具备的技能. 这里，你需要学习的是用于企业级 AI 的 Python，因为 Python 是一门内容非常广泛的语言。 实际上, Python可以学的东西非常多, 你可以持续每天花2-3个小时来进行学习.

但是, 你不需要完全学完了Python后才进入第二阶段.  你可以在有一定Python基础之后, 尝试用Python + FastAPI 来构建一个Web服务器. 

总体来说你要学习的东西包括
1. Python基础 
- for 循环
- 数据类型
- 变量
- if else等等


2. FastAPI
- 接口设计
- 后台任务
- 中间件

3. Pydantic
- 确定数据格式
- 自定义校验规则
- 嵌套模型
- 报错处理

4. 环境管理: 用 .env 文件管理不同环境的配置
5. 在 Python 里调LLM API


### 作业

- 用手写一个工单跟踪的 FastAPI 服务, 包含5 个接口
    - 新建工单
    - 列出全部工单
    - 改工单状态
    - 按 ID 查工单
    - /summarize 接口，调大模型给工单做摘要
    - 用 Pydantic 模型校验请求和返回的数据，报错处理要规范（HTTPException、格式统一的报错返回）
   
- 把项目推到 GitHub，写个 README

## 第二阶段 学习Vibe Coding
我们要做FDE, 肯定要熟练掌握怎么用AI写代码. 这个阶段我们开始学习如何Vibe Coding

1. 选一个工具, 建议是Claude Code或者Codex
2. LLM方面, 有足够经费, 选择Opus5.5, 经费不够就使用DeepSeekV4.1 Flash
3. Claude Skills, Claude.md, 上下文管理
4. 和AI编程时养成好习惯. 尽量拆成一步一步让AI来做, 并且在过程中及时纠正和验证
    1. 先做方案设计
    2. 让AI根据方案设计好测试用例
    3. 再让AI执行计划
    3. 及时验证和测试
5. AI可能出错的地方包括, 这些点都要自己去检查和不停向AI提问
    1. 给自己加戏, 编造需求
    2. 报错处理乱写
    3. 忽略关键处理
    

### 作业

- 用 Claude Code 或 Codex，给第一阶段的工单系统加功能
    - 先写一个 CLAUDE.md
    - 给项目增加5个规范, 包括命名、报错处理、文件夹结构、类型标注、不写死密钥
    - 再让 AI 加 2 个新功能  分配维修人员和任务优先级
- review AI的代码：让 AI 生成大约 100 行新功能的代码，然后不靠 AI，自己找出并修掉至少 3 个问题

## 第三阶段 学习大模型基础和RAG

需要了解一个企业, 譬如怎么修设备, 报销有什么规定, 构建企业的知识库非常重要.
这个阶段我们学习RAG

1. 了解AI的基本概念
    - 学习机器学习、深度学习、生成式AI、Agent分别是什么
    - Transformer和大模型生成文字的大致过程
    - 学习token、上下文窗口、temperature、top-p等概念
2. 文档处理
    - 从PDF、Word、Excel里取数据
    - 固定切分、递归切分、语义切分
    - 保留文档名称、页码等来源信息
3. 向量和检索
    - embedding是干什么的
    - 选一个向量库来用, 比如ChromaDB、Qdrant或者pgvector
    - 了解关键词检索、向量检索、混合检索和重排序
4. 回答要有依据
    - 回答带引用
    - 找不到资料就说不知道
    - 不要拿模型编造的东西冒充企业制度
5. 使用时, 关注回答质量, 响应时间和调用成本

### 作业

- 找10份可以合法使用的PDF, 优先选设备手册, 后面接到工单系统里
- 做一个RAG项目: 读取文档 → 切分 → 转向量 → 检索 → 回答, 记得在答案里, 要带文档名称和页码
- 把代码和运行说明放到GitHub. 不要上传客户的保密文档, 对外展示用公开或脱敏数据
